Retrograde analysis: solving backwards from checkmate

Start from every checkmate, then sweep the whole table again and again. Each pass resolves positions one move further from mate, until a pass changes nothing. This page runs the real thing on KR vs K, all 524,288 slots, in your browser.

Each number on the board is how many moves White needs to mate if the Black king stands on that square with Black to move. Hatched squares are illegal for the Black king. Squares left as plain board after the last pass are draws, usually because Black can take an undefended rook. The JavaScript solver here was checked against the engine's C++ tablebase on 700 positions with zero mismatches. On the GPU, one thread handles one position per pass, over 209,674,080 positions per 5-piece table.

9,872 ms to 575 ms, one measured change at a time

Solving KQ vs KR (3,494,568 positions, 65 passes) on an RTX 4090. Every step was re-checked bit-exact against the CPU solver before the next one. The biggest win came from the change static analysis ranked lowest.

Step gain = previous total ÷ new total. nsys shows the sweep kernel at 100% of GPU time, with launch, copy and sync overhead around 0.5%. The final kernel reaches about 2 GB/s of the 1,008 GB/s peak: it is compute-bound on move generation, not memory-bound. The next lever is a frontier work-list that only revisits positions whose successors changed.

Fig. 3 · Trust, then scale

Correct on the CPU first, then fanned out across GPUs

The GPU code is a __host__ __device__ port of the verified CPU code, so every device stage can be diffed against the CPU on a laptop with no GPU. Only then does it run at full scale in the cloud, and the results are checked once more against an outside source.

The bit-exact gates cover tables up to 4 pieces. For 5 pieces, the full CPU solve would take 15–20 hours per material, so correctness rests on the same kernels passing those gates plus the external Lichess sample, which includes each table's two deepest mates.

Fig. 4 · At full scale

Solve time follows the number of passes, and queens cost more per pass

All 28 tables are the same size, 209,674,080 positions each, yet solve times range from 7 to 85 seconds. Time grows with the passes a table needs, which grows with its deepest mate. The cost of each pass splits cleanly by whether a queen is on the board, because queens generate more moves for every thread to check.

GPU solve time only, one RTX 4090; host setup adds about 96 s per material. Lines show each group's average seconds per pass. Total GPU time for all 28 tables: 873 s.
